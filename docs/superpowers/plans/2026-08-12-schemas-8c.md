# Schémas 8C : le playbook — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ranger vingt combinaisons — dossiers, recherche, tri — et les raccrocher aux entraînements.

**Architecture:** Deux champs facultatifs (`Schema.dossier`, `Schema.majLe`) et un troisième sur `Training` (`playIds`). Les dossiers se déduisent des schémas, sans table ni entité. Aucune version Dexie ajoutée : un champ facultatif sur un document n'a pas besoin de migration.

**Tech Stack:** React 19, TypeScript, Vite, Dexie, Vitest + Testing Library, Tailwind v4. Aucune dépendance ajoutée.

## Global Constraints

- Commentaires, libellés et messages de commit **en français accentué** (`é è à ç`). Le dépôt entier est ainsi et le lint l'accepte. Si des accents disparaissent d'un fichier écrit, réécrire le fichier entier avec Write puis vérifier avec `grep -c 'à\|é' <fichier>`.
- **La lecture n'est jamais protégée** : chercher, filtrer, consulter ne demandent aucun code. Ranger, renommer, attacher passent par `guard('manage', …)`, et la convention du dépôt est **garder d'abord, muter ensuite**.
- **Aucune version Dexie ajoutée.** La base reste en v5. Si une tâche semble l'exiger, c'est que la conception est à revoir — signale-le.
- Les schémas et les entraînements ne passent pas par la file de synchronisation.
- Aucune dépendance npm ajoutée.
- Commandes : `pnpm test`, `pnpm lint`, `pnpm build` — les trois passent avant chaque commit.

- [ ] **Step 1: Écrire les tests qui échouent**

Les cas, à écrire complètement sur le modèle des tests existants du fichier :

- la barre de dossiers montre « Tous », un onglet par dossier existant, et « Sans dossier » seulement s'il y a des schémas non rangés ;
- choisir un dossier ne laisse que ses schémas dans la grille ;

- l'ordre suit `majLe`, le plus récent en tête ;
- changer le dossier d'un schéma est administratif : la table de marque se voit demander le code et rien ne change en base ;
- un visiteur cherche et filtre sans qu'aucun code lui soit demandé.

- [ ] **Step 3: Implémenter**

État local : `dossierActif: string | null` (null = « Tous »), `recherche: string`. La grille rend `schemas` filtrés puis triés par `majLe` décroissant (les schémas sans `majLe` en dernier, pour que la comparaison ne dépende pas d'`undefined`).

Sur chaque carte, une pastille de dossier qui ouvre la saisie : un `<input list="...">` avec un `<datalist>` alimenté par `dossiers(schemas)` — suggestions sans imposer de gestion de dossiers. L'enregistrement passe par `guard('manage', …)`, **la garde avant la mutation locale**.

La recherche est insensible à la casse et aux accents (`localeCompare` avec `sensitivity: 'base'`, ou normalisation `NFD` + suppression des diacritiques — au choix, mais teste-la avec un accent).

### Task 3 : L'entraînement porte ses schémas

**Files:**
- Modify: `src/ui/screens/Calendrier.tsx`, `src/ui/screens/Dashboard.tsx`
- Test: les fichiers de test correspondants

- [ ] **Step 1: Écrire les tests qui échouent**

- Dans le calendrier, attacher un schéma à un entraînement l'enregistre ; décocher le retire ; le nombre attaché s'affiche sur la ligne.
- L'attache est administrative : refusée à la table de marque, rien en base.
- Sur le tableau de bord, quand la prochaine échéance est un entraînement portant des schémas, leurs noms s'affichent et chacun mène au lecteur (`/schemas/<id>/lecteur`).
- **Un entraînement citant un schéma supprimé ne casse rien** : ni le calendrier, ni le tableau de bord, et le compte affiché est celui des schémas qui existent. C'est le garde que le projet 6 a appris en laissant un joueur supprimé dans une convocation — la cascade de la Task 1 protège l'écriture, ce test protège la lecture.

- [ ] **Step 2: Lancer et vérifier l'échec**

- [ ] **Step 3: Implémenter**

Calendrier : la ligne d'un entraînement se déplie sur une liste de cases à cocher, une par schéma du club — **le même patron que la convocation d'une rencontre dans `MatchPreview.tsx`, va le lire**. Le compte affiché filtre sur les schémas existants.

Tableau de bord : dans le bloc « prochaine échéance », si c'est un entraînement et qu'il porte des schémas existants, les lister avec un lien vers le lecteur de chacun.
